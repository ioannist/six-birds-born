# Claims and verification

Commands run from the public repository root after package installation and
`make lean`. The eight census claims use `--data "$BORN_FULL_DATA"`: either the
completed census-extension stage directory or a full `born_regenerated_bundle_v1`
bundle directory (`$DATA_OUT/full/bundle`). Set `BORN_FULL_DATA` to that path
or the completed full stage tree. For other data claims, set
`BORN_DATA_BUNDLE=/path/to/historical/bundle.json` to the separately supplied
historical `born_claim_bundle_v1` evidence; P12 also needs
`--historical-root "$BORN_HISTORICAL_ROOT"`.
See [reproduction](reproduction.md#full-cohort-public-registry) for precise inputs,
relocation, environment and fresh-clone requirements. A fresh clone can build and
run 14 commands without retained data; 17 require evidence. Every command prints
PASS or FAIL and exits accordingly; reduced or historical 120-case bundles cannot
certify a full-cohort census row.

`verify --workers N` accepts a positive integer (default **1**); only regenerated
P12 uses it, for parallel certified rotation checks. On the full profile use
`verify P12 --profile regenerated --data "$DATA_OUT/full/bundle" --workers 48`:
the completed full-profile run measured **46 min at 48 workers**, versus a
separate **9.0 h serial** measurement. Other claims ignore the flag. Historical
P12 inputs above are unchanged.

A Lean command audits the named compiled endpoints and their axioms. Python
construction controls and historical attachments are identified separately below.
Formal endpoint domains are detailed in [Lean coverage](../lean_born/COVERAGE.md).

`verify --list` is the registry; `make verify` runs all claims without local data.
A successful historical verification certifies the specified evidence check,
not fresh confirmation. In particular, TB01 verifies an informative negative.
The library also exposes explicit-input construction and census utilities;
those are not additional verification claims.
